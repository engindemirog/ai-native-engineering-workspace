## Ordered steps
1. **Stage and table** `[plan 0006/1]`.
   - `scripts/status` lists `specs/active/` and `specs/done/`.
   - Each spec is paired with its plan the way doctor pairs them (`NNNN-` prefix).
   - It reads `- Status:`, `- Approved by / on:` (HTML comments stripped; empty, `-` or `—` means
     not approved; the same `sed` as doctor), the last `CHECK GREEN (full,` line, and the
     `### Review round` and `### VERIFY round` tables.
   - It applies Requirement 2's rules in order and prints the table with the empty and unclear
     states.
   - Selftest fixtures: one per stage (AC-1–AC-3).
2. **Stale evidence** `[plan 0006/2]`.
   - The proving sha is taken from the last full line.
   - `git cat-file -e <sha>^{commit}` decides whether the sha is known.
   - `git diff --name-only <sha> HEAD -- . ':!specs' ':!.anew-dev'` must be empty. Uncommitted
     changes outside specs/ count too: `git status --porcelain` with the same exclusions.
   - Fixtures cover a code commit, a specs-only commit and an unknown sha (AC-4).
3. **Changed after approval** `[plan 0006/3]`.
   - The approval commit is the oldest commit whose plan text holds a non-empty
     `Approved by / on` line: `git log --format=%H --reverse -S'- Approved by / on:' -- <plan>`,
     then the first one whose version parses as approved.
   - For each file, an awk filter prints only the approved regions:
     - spec: Intent, Requirements, User experience, Constraints, and the criterion lines with the
       box and any `→ moved to …` tail cut off;
     - plan: Files, Ordered steps, Risks, Criterion ↔ test map.
   - The filter runs on `git show <commit>:<path>` and on the working file, and the outputs are
     compared.
   - The spec path is followed across `active/`→`done/` (`git log --follow` is not needed: the
     path at the approval commit is read from that commit's tree).
   - A difference in the plan with a new `A-<n>` line in `## Amendments` (compared the same way)
     reads "amended (A-<n>)".
   - Fixtures cover a steps change, a criterion-text change, the same with A-1, and ticks, status
     and evidence only (AC-5). They also cover no git (a copy without `.git`) and an uncommitted
     approval (AC-6).
4. **`--json`, the usage, read-only** `[plan 0006/4]`.
   - `--json` prints `{"anew_status":1,"rows":[{"spec","name","spec_status","plan_status",
     "stage","who","next","warnings":[…]}],"notes":[…]}`.
   - Strings are escaped for `\` `"` and control characters by one awk function.
   - Selftest compares exact output for a two-row fixture. The unknown argument exits 2. A
     `git status --porcelain` before/after comparison covers AC-8. (AC-7, AC-8)
5. **Docs and release** `[plan 0006/5]`: commands.md, README, CHANGELOG v1.25, `.anew-version`
   (AC-9).
6. Review (subagent) → triage → fix rounds → VERIFY (subagent) → PR, squash-merge, then tag
   v1.25 and release it as Latest. `lts/1.24` is untouched.

## Risks & open questions
1. **The stage rules duplicate `workflows/segments.md`.** If segments.md changes, status can
   drift.
   - Recommendation: status prints segments.md's own wording for who and next.
   - Recommendation: the commands.md section says "status follows segments.md; a change there
     changes status". Selftest guards each stage.
2. **The triage parse is the weakest part** (spec G-3).
   - Recommendation: read only the Verdict column and the Note cell's `fix-<n>` or sha. Anything
     else reads as open, so the error falls on the safe side.
3. **Performance.** There is one `git log -S` per active plan, and shipped work skips the
   checks. That is fine for tens of specs. Recommendation: accept.
4. **Windows Git Bash.** It is the same tool set as doctor, so the risk is low.
   - Recommendation: no `mapfile`, no `local`, CRLF stripped as in doctor.
   - Recommendation: selftest runs locally on Windows, and CI on Linux.
5. **Environment:** template workspace, with doctor's usual WARNs (no check.conf, no adapter).
   Evidence is doctor --strict + selftest, as for 0004/0005. Never run two selftests at once: the
   residue tests are load-sensitive.
