## Risks & open questions
1. **The rest of the activation after an Add** must run without a reload. Recommendation: the
   activation body becomes a function of the root, called at startup when ANEW is there and after
   an Add; a test-free part of the VS Code layer, covered by the human's run.
2. **The network** (the API's rate limit, a proxy, offline): the API call and the clone are the only
   network steps; a failure is shown as it is, nothing written. Recommendation: no retries, no
   cache.
3. **Windows paths** (a temporary folder with spaces, the shell from `anew.shell`): adopt runs
   through the same `runScript` as gate, with the target as one argument.
4. **The template's own `scripts/adopt` is what runs**: a release older than v1.30 has none.
   Recommendation: refused with "this release has no scripts/adopt (needs v1.30 or later)" — the
   latest release is v1.30 from the moment this ships.
5. **Environment:** low memory: one selftest or npm run at a time.
