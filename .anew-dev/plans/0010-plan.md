## Risks & open questions
1. **Splitting a free-form report** can miss or mis-split findings. Recommendation: test it on
   the six real 0009 reports; when a finding is missed, the human adds it by hand on the screen;
   the screen shows the count it found next to the pasted text, so a miss is visible. Never a
   guessed verdict: verdicts are the human's, the recommendation is only shown.
2. **Start in Claude Code** depends on `claude` on PATH and its argument form. Recommendation:
   `claude "<command>"` in a new VS Code terminal (an initial prompt); offered only when found;
   Copy otherwise. The AC-7 run proves it on this machine.
3. **Push and open PR** writes outside the machine. Recommendation: offered only after a written
   ship, when `gh auth status` succeeds and the branch is not the default; a modal confirmation
   names branch and remote; it runs `git push -u <remote> <branch>` and `gh pr create --fill`
   and shows their output as it is; otherwise the two commands with Copy. Never a merge.
4. **The backlog append** is the one file the extension writes itself. Recommendation: the
   entry is shown in the preview before Save; appended in the template's format; then gate's
   triage call (which checks the `B-<n>`) — if gate refuses, the entry stays and the screen says
   so (the human removes it or retries).
5. **The webview sidebar's accessibility.** Recommendation: buttons in reading order,
   `aria-label` per card (number, name, decision), focus visible, no colour-only meaning; tested
   on the HTML; the human's run with the keyboard at SHIP.
6. **Size** (G-6): the extension roughly doubles. Recommendation: one step per screen, each with
   its tests in the same commit; review reads step by step.
7. **Environment:** doctor --strict on this machine: 0 fail, 5 warn (expected); Node 24, VS Code
   1.137, `gh` signed in; `claude` on PATH to be checked in step 3. Low memory: one selftest or
   npm run at a time.
