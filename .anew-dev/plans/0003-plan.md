## Ordered steps
Order: the script first (the only code, and the only part with a test), then the documents
that describe it, then the independent document groups.

1. **residue attribution** `[plan 0003/1]` (Req. 1, AC-1–3).
   - `measure` writes `pid<TAB>ppid<TAB>start<TAB>command`.
     - POSIX: `ps -e -o pid= -o ppid= -o args=`, with `start` left empty.
     - Windows: `ParentProcessId` and `CreationDate`, the latter as a sortable string.
   - For each survivor, an awk pass over the last snapshot walks the parent chain (depth ≤ 64):
     - parent missing from the snapshot, or (Windows) created after the child, i.e. a reused PID
       → **gone** → check's;
     - parent alive, in the baseline, and NOT in the residue test's own ancestry
       → **not from check**;
     - POSIX: parent in the ancestry (PID 1 always included, plus the chain from `$$` up).
       Reparenting to init or a subreaper lands exactly here → check's. This covers both "init"
       and "subreaper" without detecting subreapers, and makes G-1 fall out by construction;
     - parent new and alive → go one level up;
     - depth exceeded or a cycle → check's (fail closed).
   - Windows does not reparent, so it uses no ancestry rule. This avoids blaming check for
     processes VS Code or a terminal start meanwhile.
   - Output per run:
     - `after run n: P processes, k survivor(s), m not from check[; memory …]`;
     - `  survivor  <pid>  <cmd>  (parent <ppid> <name> | gone)`;
     - `  not from check  <pid>  <cmd>  (parent <ppid> <name>)`.
   - Memory beyond the tolerance → `— over the T MB tolerance (informational)`; `found` is not
     touched.
   - Memory source by `uname`: Linux uses /proc/meminfo, Darwin uses vm_stat. This makes the
     vm_stat path fakeable and is more correct.
   - Header comment and the FOUND message are updated.
   - selftest:
     - (a) the fake ps prints ppid, with `$$`-independent fixtures:
       - init 1;
       - a baseline "other session" 100 (ppid 1);
       - after the baseline: 4244 (ppid 100) → not from check, CLEAN, exit 0;
       - 4245 (ppid 1) → survivor;
       - chain 4246 → 4247 → 9999 (gone) → both survivors;
       - the kernel thread and the zombie stay as they are.
     - (b) real foreign process: a watcher started before residue (a sibling, not an ancestor)
       spawns `sleep 25 <marker>` once a check step touches a file. The marker is listed as not
       from check, CLEAN, exit 0. Watcher and sleep are killed afterwards, also on failure.
     - (c) the real leak test keeps its assertion and adds `(parent `.
     - (d) fake Darwin + vm_stat: high, then low → `(informational)`, CLEAN, exit 0.

## Risks & open questions
- **Windows path coverage.** CI runs Ubuntu only, so the PowerShell branch is proven by running
  the selftest locally on this Windows 10 machine (output shown in the build handoff) and then by
  the pilot after upgrade (pilot B-2). Recommendation: accept; adding a Windows CI job is its own
  decision, and there is no incident for it.
- **POSIX false FOUND.** A process that a residue ancestor (e.g. a terminal) starts meanwhile
  counts as check's. It fails closed, and its parent is named. Recommendation: accept (G-1 logic).
- **Windows PID reuse.** Handled by the creation-time comparison. Without it, attribution would
  fail open.
- **Selftest timing (b).** The watcher polls a file. Settle is 1 s and the sleep lives 25 s, the
  same margins as the existing leak test.
- **Environment.** This machine: `doctor` 0 fail, 5 warn (no adapter etc., as on main). This
  template's check is `doctor --strict` + `selftest` (CI on ubuntu-latest). No unmet
  prerequisite.
