## Ordered steps
Scripts first — the documents describe behavior that must already exist and be tested.

1. **Format + check.** `requires <step name>: <command>` — one line per prerequisite, `<step name>`
   as displayed (without `[fast]`). check reads the conf in two passes: pass 1 collects the
   profile's steps and their prerequisites, dedupes by exact command text, runs each once
   (`cd $ROOT && sh -c "$cmd" </dev/null`, output captured); met → `ok    prerequisite: <cmd>
   (steps: a, b)`; unmet → its output, then `CHECK FAILED (<label>) prerequisite not met: <cmd>
   (steps: a) — environment gap, see prompts/recovery/environment-gap.md (R-13)`. All unmet ones
   are reported, then exit 1 before any step. Pass 2 is today's loop, skipping `requires` lines.
   Selftest scenarios for AC-1, AC-4, AC-5, AC-6, AC-10 in the same commit. `[plan 0001/1]`
2. **doctor.** Same parsing (copied, as the existing "same rule as check" blocks are — no shared
   library: scripts must stay copyable one by one on upgrade). Every prerequisite, both profiles,
   once per command; per command `ok`/`WARN` (+ output when unmet); then one line per profile:
   `ok    profile <p>: runnable on this machine` or `WARN  profile <p>: not runnable on this
   machine (steps: …) — environment gap, R-13`. Nothing printed when no `requires` line exists.
   WARN in `--strict` too. Selftest for AC-2, AC-3, AC-10. `[plan 0001/2]`
3. **residue + example conf.** residue's step detection skips `requires` lines; example conf
   gains the format with a tool-neutral example (a toolchain version check) and, commented, two
   container-runtime alternatives side by side. Selftest: residue on a `requires`-only conf says
   NOT MEASURED. AC-9 grep run. `[plan 0001/3]`
4. **R-13 ramp + catalog.** `environment-gap.md` in the ramp format (situation, protection rules,
   prompt, exit evidence); README table row; doctor count 13; all "R-01…R-12" references. `[plan 0001/4]`
5. **Gates in the process.** bootstrap VERIFY reports doctor's per-profile verdict with a
   recommendation for a non-runnable profile; plan prompt + template Risks list unmet
   prerequisites; build prompt + segments BUILD entry print the verdict and stop on R-13 when it
   differs from the plan. `[plan 0001/5]`
6. **Reference, ADR, release.** commands.md, testing.md line, ANEW-0011, CHANGELOG v1.21,
   `.anew-version`. Last: `./scripts/doctor --strict`, `./scripts/selftest`, full green. `[plan 0001/6]`

## Risks & open questions
- **Q1 — A `requires` line naming no existing step** (a typo would silently disable the
  prerequisite). The spec does not cover it. *Recommendation:* check fails (exit 1, `requires
  names no step: <name>`), doctor WARNs. Same severity as an unmet prerequisite; never silent.
  Adds one selftest scenario, no new AC (it guards AC-4).
- **Q2 — Old scripts reading a new conf.** A v1.20 check treats `requires x: cmd` as a step named
  "requires x" and runs the command as a step — fails fast if unmet, never a false green.
  *Recommendation:* accept; state it in CHANGELOG Upgrading (update scripts before the conf).
- **Q3 — Step names containing `:`** cannot be referenced (`requires` splits at the first `:`
  like steps do). *Recommendation:* document, no code — a step name with `:` is already
  impossible today.
- **Q4 — `.anew-dev/` ships with "Use this template".** GitHub copies the whole repo.
  *Recommendation:* the README line asking users to delete it now; an automatic removal in
  bootstrap belongs to spec 0004 (template notes).
- **Q5 — This repo's own check.** The template has no `scripts/check.conf`; its CI proof is
  `doctor --strict` + `selftest`. *Recommendation:* "check green" for this spec = those two green
  (CI and local); no check.conf added to the template.
- Environment (spec Req. 6): no prerequisite needed here — POSIX sh, git, awk, sed only.
  This machine: Linux; macOS and Git Bash are covered by POSIX-only constructs, not by a run.
