## Risks & open questions
1. **Node 24's type stripping for tests** keeps the tests free of a build step, but imports must
   name `.ts` files and only erasable TypeScript is allowed (no enums, no namespaces).
   Recommendation: accept; `tsconfig` sets `allowImportingTsExtensions` and
   `erasableSyntaxOnly`, so tsc refuses what Node cannot strip. CI pins Node 24.
2. **Windows shell detection.** Git for Windows puts `git.exe` in `<root>/cmd/`; `bash.exe` is in
   `<root>/bin/`. Recommendation: derive from `git` on PATH, fall back to the setting; a test
   covers the path logic with a fake layout.
3. **Screenshots of a VS Code screen** can't be taken headless here (low memory, no VS Code
   driver). Recommendation: the panel's HTML is rendered headless by Playwright (already in the uv
   cache) with VS Code's dark and light theme variables stubbed — one image per state; the tree
   view and the real install are seen by the human at SHIP (they open the pilot clone in VS Code
   with the `.vsix` installed). The evidence table says which is which.
4. **The approval screen's "opened" check** is the editor reporting the file open, not proof of
   reading — the same limit as the mockup. Recommendation: accept; it removes the summary-only
   approval, which is what the correction asked for.
5. **Template users get `extensions/`.** Recommendation: CHANGELOG and README say it is optional;
   doctor and selftest ignore it.
6. **Environment:** doctor --strict on this machine: 0 fail, 5 warn (expected); Node 24.11, npm
   11.6, VS Code 1.137 present. Memory is low: one selftest or npm run at a time.
