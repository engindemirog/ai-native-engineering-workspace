## Ordered steps
1. **Status: open investigate** `[plan 0007/1]`.
   - `newest_round` also prints the ids of `investigate` rows (a second marker, e.g.
     `investigate<TAB><finding>`); the main loop gathers them before the stage rules.
   - Rule placed after "unknown heading" and before FIX ROUND: any investigate in the newest
     round → `unclear: investigate open — <ids> in '<heading>' (R-05: QA investigates; a new
     round records the verdict)`.
   - Selftest: an investigate-only VERIFY round reads unclear, not SHIP; one beside an open real
     still reads unclear. The 81 status scenarios stay as they are (AC-8).
2. **Gate frame** `[plan 0007/2]`.
   - `scripts/gate <approve-spec|approve-plan|triage|ship> NNNN [options]`; usage and exit 2 on
     anything else; `NNNN` must be four digits.
   - Refusals (exit 1): no git work tree; empty `git config user.name`; no
     `specs/active/NNNN-*.md` (or two).
   - Stage: run `scripts/status --json` from the same directory and cut the row with
     `"spec":"NNNN"` out of the one-line document with awk; read its `stage`, `warnings` and
     `notes` strings (the documented shape; JSON escapes undone for display only).
   - Writes go through awk into a temp file in the same directory, then `cat > target` (keeps
     the file mode; no `sed -i`); a trap removes the temp file.
   - Commit: `git add -- <paths>` for the paths gate wrote, then `git commit -q -m "<msg>" --
     <paths>` (pathspec commit: other staged entries stay staged and out of it). Before writing,
     `git status --porcelain -- <target>` tells whether the target held uncommitted edits
     (staged and untracked too), for the "committed with your uncommitted edits" line (A-2).
   - A failed commit (a hook, signing) restores every path gate wrote, and undoes a move, to
     where it was before the run, and says so: a refusal writes nothing (A-2).
   - Message: `gate: <gate> NNNN — <what>`.
3. **approve-spec, approve-plan** `[plan 0007/3]`.
   - approve-spec: stage must be `ANALYZE`; rewrites the first `- Status:` line to `Approved`.
   - approve-plan: the spec's status must be `Approved` or `In progress`, and the plan file must
     exist. Stage `PLAN` with who `human` → first approval; any non-shipped stage with an
     approved plan → re-approval. Rewrites `- Status:` to `Approved` and the `- Approved by / on:`
     line to `<name>, <YYYY-MM-DD>` — the trailing HTML comment of the template line is dropped
     (it spans lines: removed up to its `-->`). Same value as the current one → append
     ` (re-approved)`; same value with `(re-approved)` already → refuse (exit 1, "already
     re-approved today").
   - Selftest: first approval → status BUILD; Draft spec refuses; no plan refuses; a re-approval
     clears a spec drift warning; the untouched template line reads approved after (AC-1, AC-2).
4. **triage** `[plan 0007/4]`.
   - `triage NNNN --review|--verify [--finding "<text>" <verdict> "<note>"]…`.
   - Stage: `--review` needs `REVIEW`, `--verify` needs `VERIFY`; either is taken at
     `unclear: investigate open`, whose next step is a new round (A-1).
   - Checks first (exit 2, nothing written): the verdict list; noise needs a note; defer's note
     needs a `B-<n>` that `specs/backlog.md` holds as `**B-<n>**`; text or note with `|` or a
     line break, or empty text.
   - Round number: count of `### Review round` (or `### VERIFY round`) headings under `## Triage`,
     plus one. Appends heading, header row, separator row and the rows at the end of
     `## Triage` (before the next `## ` heading, or end of file). Zero findings → the heading
     only.
   - Selftest: a review round with real → FIX ROUND; a clean review round → VERIFY; a clean
     VERIFY round → SHIP; each bad input leaves file and index unchanged (AC-3, AC-4).
5. **ship** `[plan 0007/5]`.
   - Stage must be `SHIP`, with no warning and no "approval is not committed" note.
   - In the spec, criterion lines by doctor's definition — the first checkbox followed by an
     `AC-`/`CB-`/`PB-` id, any bullet and section, so a mini spec too — are ticked unless moved
     out by doctor's rule (the id struck, a `→ moved to` / `-> moved to` target after it); a
     struck id with no target refuses before writing, and so does a moved-out criterion doctor
     would fail: a target that is neither a `B-<n>` in the backlog nor `spec <NNNN>` in
     `specs/active/` (not itself), or any moved-out criterion in a sensitive-area spec (A-3). Every `- [ ]` under
     `## Definition of Done` → `- [x]`; `- Status:` → `Shipped`. Then `git mv` to `specs/done/`;
     the plan's `- Spec:` line points at the new path, and a Spec line that does not name the
     old path refuses before writing (A-2).
   - One commit with the old path, the new path and the plan.
   - Selftest: the shipped fixture passes `doctor --strict`'s new-ship checks; a struck
     criterion stays unticked; a warning or another stage refuses; an unrelated staged file stays
     staged; edits named (AC-5, AC-6). No git / no user name / unknown spec / bad argument
     (AC-7).
6. **Docs and release** `[plan 0007/6]`: the files above (AC-9).
7. Review (subagent) → triage → fix rounds → VERIFY (subagent) → PR, squash-merge, tag v1.26,
   release as Latest. `lts/1.24` untouched.

## Risks & open questions
1. **Gate depends on status's JSON.** A change to the row shape breaks gate. Recommendation:
   accept — it is the documented shape, stable within a minor, shipped in the same repo, and the
   selftest runs both together.
2. **A pathspec commit with a rename.** `git commit -- old new plan` after `git mv` should record
   the move. Recommendation: prove it in step 5's selftest; if git refuses, commit with the same
   paths staged and the rest of the index saved and restored (`git write-tree`/`read-tree`).
3. **Agents and the prompts.** `/plan` and the segment prompts still tell an agent to write the
   approval line on the human's word. Gate does not change that. Recommendation: leave the
   prompts as they are; gate is an optional way to write the same line, and the roles README
   line covers who decides.
4. **Fail direction.** Every check refuses rather than writes; status, not gate, decides the
   stage, so the two cannot disagree. Recommendation: accept.
5. **Environment:** doctor --strict on this machine: 0 fail, 5 warn (the template's expected
   warnings); no step prerequisite unmet. Memory is low: one selftest at a time, run in the
   foreground of the build step only.
